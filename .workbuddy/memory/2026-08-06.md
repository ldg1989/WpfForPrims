# 2026-08-06 工作日志

## WpfForPrims - 点击按钮不显示用户控件

**项目背景**：基于 Prism 8.1.97 + DryIoc 的 WPF(.NET 8) 模块切换 demo。

**症状**：用户口述的"MainView"实际为 `WpfForPrims/Views/MainWindow.xaml`。点击"模块A/B/C"按钮，下方 ContentControl 没有任何反应。

**根因**：View 和 ViewModel 用了两套互不相干的模块切换机制，谁也没接上谁：

- View：ContentControl 上声明了 `prism:RegionManager.RegionName="ContentRegion"`，但代码里没有任何地方调用 `RequestNavigate`。
- ViewModel：`ShowContentFunc` 通过 `ShowContent = new UCA()` 改一个普通属性，但 ContentControl 没写 `Content="{Binding ShowContent}"`，UI 不会刷新。
- 附带：ContentControl 的 `Height="100"` 加上 UserControl 里 `FontSize="80"` 的 TextBlock，会让文字被截断。

**修法**（两套都给用户）：

1. **最小改动方案**：只改 `MainWindow.xaml` 一行——给 ContentControl 加 `Content="{Binding ShowContent}"`，去掉 `Height` 和 `RegionName`。VM 不动。
2. **Prism 标准写法**：在 `App.xaml.cs` 用 `RegisterForNavigation<UCA/UCB/UCC>()` 注册；`MainWindowViewModel` 构造函数注入 `IRegionManager`，命令里 `_regionManager.RequestNavigate("ContentRegion", viewName)`；XAML 恢复 `RegionName`、拿掉 `Content` 绑定。

**结论**：项目目前体量小，理论上用最小改动方案即可；如后续要做 Backstack、导航日志、模块解耦，再切到 Region 导航方案。

## 后续：用户最终选了方案二（Prism Region 导航）

用户反馈"代码给误删了"，重做一次方案二。检查时发现三个文件状态不齐：`App.xaml.cs` 已是方案二（`RegisterForNavigation<UCA/UCB/UCC>()`），但 `MainWindow.xaml` 仍是方案一（`Content="{Binding ShowContent}"`），`MainWindowViewModel.cs` 又回到了最早手写 `new UCA()` + 属性的版本。

直接把 VM 改成构造函数注入 `IRegionManager`、`RequestNavigate("ContentRegion", viewName)`，XAML 恢复 `prism:RegionManager.RegionName="ContentRegion"` 即可。最终三个文件均已切到方案二，可以正常导航。
